L'errore ArgumentCountError non dipende dal nome della variabile, ma da come stai invocando la policy nella Route (tramite il middleware can).

Nel middleware della rotta hai scritto:
middleware: can:update,App\Models\FederationMore

Passando la stringa della classe App\Models\FederationMore invece dell'istanza del modello, Laravel invoca la Policy passando solo l'utente autenticato (1 argomento), trattando la richiesta come un'azione generica sulla classe e non su un record specifico. Poiché il metodo update() della Policy si aspetta 2 argomenti (User $user, FederationMore $federationMore), PHP solleva l'eccezione.

Soluzioni
Devi indicare a Laravel di passare il modello risolto dalla rotta (cioè l'istanza con ID 7) al posto del nome della classe.

Opzione A: Correggere il Middleware nella Definizione della Rotta (Consigliata)
Nella definizione della rotta (nel file routes/web.php), sostituisci la stringa della classe con il nome del parametro della rotta (federation_more):

PHP
// PRIMA (Sbagliato - passa la classe invece del modello):
Route::get('/federation-more/modify/{federation_more}', ...)->middleware('can:update,App\Models\FederationMore');

// DOPO (Corretto - passa il modello risolto):
Route::get('/federation-more/modify/{federation_more}', ...)->middleware('can:update,federation_more');
Opzione B: Utilizzare la Type-Hinting Implicita del Controller
Se utilizzi un Controller, rimuovi il middleware can dalla rotta e usa la scansione implicita direttamente nel Controller:

PHP
// Nel Controller
public function edit(FederationMore $federationMore)
{
    $this->authorize('update', $federationMore);

    return view(...);
}

Firma del metodo nella Policy: Assicurati che nel file app/Policies/FederationMorePolicy.php il metodo sia definito così:

PHP
public function update(User $user, FederationMore $federationMore): bool

}
