### 2. aggiugiMi all'organization X

Completato il blade ma si configura un "problema calendario".
Il Model UserRole ha anche un paio di date che sono *role_opening* e
*role_closing*. Quando l'incarico comincia e quando termina. Questo rende la tabella "temporale" ovvero lo stesso id per date diverse cambia valori, oppure dal .. al .. vale, fuori no.  
Quando si va a creare un nuovo record occorre
andare a testare se questo nuovo record "si sovrappone"
come calendario a uno preesistente. Se sì,
prima e/o dopo le date del nuovo record vanno modificati
i record esistenti per creare un "passaggio" di consegne
tra i diversi record.

- Caso 1: record_vecchio.role_closing > record_nuovo.role_opening  
  in questo caso va modificato record_vecchio.role_closing
   impostando record_vecchio.role_closing = record_nuovo.role_opening
- Caso 2: record_vecchio.role_opening < record_nuovo.role_closing  
  anche in questo caso viene aggiornato record vecchio,
  impostando record_vecchio.role_opening = record_nuovo.role_closing

Questo va fatto con un *Observer*, prima o dopo un *create* del nuovo record.  
Invece no, sostiene Gemini che in questo caso è più pratico
fare una funzione nel Model, che tramite DB:transaction()
consente di fare le verifiche, e le modifiche con un
solo, eventuale, rollback.

Ecco come puoi estendere il tuo file di test Pest includendo i due nuovi casi:

```php
use App\Models\User;
use App\Models\UserContact;
use App\Models\Organization;
use App\Models\UserRolesRoleContext;
use App\Models\UserRole;
use Livewire\Volt\Volt;
use Illuminate\Support\Str;

beforeEach(function () {
    $this->user = User::factory()->create([
        'email_verified_at' => now(),
    ]);

    $this->userContact = UserContact::firstOrCreate(
        ['id' => $this->user->id],
        [
            'email' => $this->user->email,
            'first_name' => 'Mario',
            'last_name' => 'Rossi',
            'country_id' => 'ITA',
        ]
    );

    $this->organization = Organization::factory()->create([
        'id' => Str::uuid7(),
        'country_id' => 'ITA',
    ]);
});

it('allows authenticated users to access organization.user.add page', function () {
    $this->actingAs($this->user)
        ->get(route('organization.user.add', ['organization' => $this->organization]))
        ->assertSuccessful()
        ->assertSeeLivewire('organization.user.add');
});

it('successfully adds user to organization with member role', function () {
    // Assicuriamo che il ruolo 'member' esista nel DB per superare la validazione 'exists:user_roles_role_sets,role'
    UserRolesRoleContext::factory()->create([
        'context_type' => 'organizations',
        'role'         => 'member',
        'green'        => true,
    ]);

    $this->actingAs($this->user);

    Volt::test('organization.user.add', ['organization' => $this->organization])
        ->set('userRoleRole', 'member')
        ->call('addUserToOrganizationInUserRole')
        ->assertHasNoErrors()
        ->assertRedirect(route('user.dashboard'));

    // Verifica la presenza del record nella tabella dei ruoli utenti
    $this->assertDatabaseHas('user_roles', [
        'user_id'         => $this->userContact->id,
        'organization_id' => $this->organization->id,
        'role'            => 'member',
    ]);
});

it('fails validation when providing an invalid role like something', function () {
    $this->actingAs($this->user);

    Volt::test('organization.user.add', ['organization' => $this->organization])
        ->set('userRoleRole', 'something')
        ->call('addUserToOrganizationInUserRole')
        ->assertHasErrors(['userRoleRole' => 'exists']);
});

```

### Note principali

1. **Piattaforma Volt**: Utilizzando `Volt::test('organization.user.add', ['organization' => $this->organization])`, simuli il binding del componente inserendo la proprietà `$organization`.
2. **Setup del ruolo valido**: La regola di validazione definita nel componente richiede `exists:user_roles_role_sets,role`. Per il primo test, è necessario che la tabella contenga una riga con `role = 'member'`. Nel test viene creato direttamente tramite il model `UserRolesRoleContext` (o la sua relativa factory).

3. **Database Assertion**: `assertDatabaseHas` controlla che l'azione `addUserToOrganizationInUserRole` abbia salvato correttamente il record `UserRole` nel
 database.
