### 🔍 Dettaglio dei Bug Riscontrati

#### 1. ❌ ContestAward::contestSection() — Ritorna sempre null

  • File: ContestAward.php:149-153
  • Codice attuale:
    public function contestSection(): BelongsTo
    {
        $section = $this->belongsTo(ContestSection::class);
        return $section;
    }

  • Causa: Eloquent deduce per default come foreign key contest_section_id. Tuttavia, nella tabella contest_awards la colonna si chiama section_id. Di conseguenza, Eloquent interroga where contest_sections.id is null e la relazione fallisce sempre
  restituendo null.
  • Correzione:
    public function contestSection(): BelongsTo
    {
        return $this->belongsTo(ContestSection::class, 'section_id', 'id');
    }

  ──────

### 1. Approfondimento su ContestAward::userWork() (ex Punto 4)

  L'ipotesi di collegare userWork tramite:

    public function userWork(): BelongsTo
    {
        return $this->belongsTo(UserWork::class, 'winner_user_id', 'user_id');
    }

  presenta due criticità strutturali verificate direttamente sul database:

  1. winner_user_id è null per le opere vincitrici:
  Quando un premio viene assegnato a un'opera fotografica (1° premio, menzione, ecc.), l'applicazione valorizza winner_work_id (con l'UUID di contest_works), lasciando winner_user_id = null.
  Eseguendo la query con winner_user_id, Laravel esegue:
    select * from `user_works` where `user_works`.`user_id` is null
  restituendo null per tutti i premi assegnati alle opere.
  2. Un autore ha più opere (1:N):
  La colonna user_id in user_works non è una chiave primaria né univoca (un concorrente carica più foto). Se anche winner_user_id fosse valorizzato (es. per il premio Miglior Autore), un belongsTo caricherebbe arbitrariamente la prima foto trovata
  dell'utente, non l'opera specifica.

#### ✅ Soluzione corretta per accedere all'opera vincente

  La catena reale delle tabelle è:
  contest_awards.winner_work_id → contest_works.id → contest_works.user_work_id → user_works.id.

  • Opzione A (Standard già usato nelle view es. listed.blade.php):
    $contestAward->contestWork?->userWork

  • Opzione B (Relazione diretta su ContestAward via HasOneThrough):
    use Illuminate\Database\Eloquent\Relations\HasOneThrough;

    public function userWork(): HasOneThrough
    {
        return $this->hasOneThrough(
            UserWork::class,
            ContestWork::class,
            'id',             // FK su ContestWork (contest_works.id)
            'id',             // FK su UserWork (user_works.id)
            'winner_work_id', // Local key su ContestAward (contest_awards.winner_work_id)
            'user_work_id'    // Local key su ContestWork (contest_works.user_work_id)
        );
    }
  (Testata in Tinker: restituisce immediatamente l'opera corretta es. "Lottatori n.1", "Clouds", ecc.).
