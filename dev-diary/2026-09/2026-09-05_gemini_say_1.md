# Chied a Gemini del 5 settembre 2026

## Domanda 1

(con allegato) Per questa blade devo validare in maniera diversa alcuni campi in base al valore true di under federation patronage. Se contestSectionUnderPatronage === true, allora contestSectionFederationId diventa required, allora contestSectionFederationSectionId diventa required e contestSectionCode diventa nullable. il comportamento del modulo tanto quanto l suo aspetto sono condizionati.

## Rsposta 1

Per implementare questo comportamento condizionale in Livewire, dobbiamo agire su tre fronti:

1. **La validazione dinamica (`rules()`)**: Le regole devono cambiare in base al valore booleano di `contestSectionUnderPatronage`.
2. **Lo stato del form (`updatedContestSectionUnderPatronage`)**: Quando l'utente spunta o deseleziona il patrocinio, dobbiamo pulire o ripristinare i campi dipendenti per evitare dati residui o incongruenti.
3. **L'aspetto visivo e il comportamento in Blade (`@if`)**: Rendere i campi *readonly*, disabilitati o modificarne la struttura grafica (es. nascondere i selettori della federazione se non c'è patrocinio).

Ecco come puoi modificare il tuo componente Volt.

### 1. Modifiche al componente Volt (Logica e Regole)

Sostituisci il metodo `rules()` e aggiungi un hook per gestire il cambio di stato di `contestSectionUnderPatronage`:

```php
    // Viene richiamata quando cambia lo stato del patrocinio
    public function updatedContestSectionUnderPatronage($value): void
    {
        if (!$value) {
            // Se tolgo il patrocinio, pulisco i campi legati alla federazione
            $this->selectedFederationId = null;
            $this->selectedSectionCode = null;
            $this->contestSectionFederationId = '';
            $this->contestSectionFederationSectionId = 0;
        }
    }

    public function rules()
    {
        return [
            'contestSectionUnderPatronage' => 'nullable|boolean',
            
            // Se under patronage è true -> required, altrimenti nullable
            'contestSectionFederationId' => $this->contestSectionUnderPatronage 
                ? 'required|string|uppercase|exists:federations,id' 
                : 'nullable|string|uppercase',

            'contestSectionFederationSectionId' => $this->contestSectionUnderPatronage 
                ? 'required|exists:federation_sections,id' 
                : 'nullable',

            // Se under patronage è true -> nullable (perché scelto dalla federazione), altrimenti required
            'contestSectionCode' => $this->contestSectionUnderPatronage 
                ? 'nullable|string|uppercase' 
                : 'required|string|uppercase',

            'contestSectionNameEn' => 'required|string|max:250',
            'contestSectionNameLocal' => 'nullable|string|max:250',
            'contestSectionSynopsis' => 'nullable|string|max:2000',
            'contestSectionFileFormats' => [
                'required',
                'string',
                'lowercase',
                new ValidFileFormats(),
            ],
            'contestSectionMinWorks' => 'required|integer|min:0|max:12',
            'contestSectionMaxWorks' => 'required|integer|max:12|gte:contestSectionMinWorks',
            'contestSectionShortSizeMax' => 'required|integer|min:2|max:4000',
            'contestSectionLongSizeMax' => 'required|integer|max:4000|gte:contestSectionShortSizeMax',
            'contestSectionFileSizeMax' => 'required|integer|min:100000|max:6000000',
            'contestSectionMonochromaticRequired' => 'nullable|boolean',
            'contestSectionRawRequired' => 'nullable|boolean',
            'contestSectionUniquePrize' => 'nullable|boolean',
        ];
    }

```

*Nota: Ricordati di gestire correttamente il salvataggio in `addContestSection()` per il campo `contestSectionFederationSectionId` nel caso in cui sia `nullable` (evitando che passi `0` se non è un ID valido).*

Nel blocco HTML, condizioniamo la visibilità dei selettori delle sezioni federali e l'attributo `required` o `readonly` dei campi in base a `$contestSectionUnderPatronage`.

### Cosa cambia con questa configurazione

1. **Validazione dinamica**: Se `contestSectionUnderPatronage` è `true`, i campi `contestSectionFederationId` e `contestSectionFederationSectionId` diventano obbligatori (`required`), mentre `contestSectionCode` diventa opzionale/nullable (perché viene ereditato in automatico dalla scelta della federazione tramite il metodo `updatedSelectedSectionCode`). Se è `false`, accade esattamente il contrario.
2. **UI reattiva**: L'attributo `:required` e `:readonly` sul campo `contestSectionCode` si adatteranno dinamicamente allo stato di spunta del patrocinio.
