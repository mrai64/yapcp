## feat/0348-user-work-import

Un conto è import di un file "come in origine",
un altro è inserire le foto e le schede. I file immagini
possono essere sostituiti da un segnaposto ma poi deve esserci
una sostituzione.

```yaml
userWork: 
  id: foto1 
  ...
UserWorkMore:
  id: new | fotomore1
  user_work_id: foto1
  ...
```

Dal manuale aggiungo il file skeleton molto infarcito
di indicazioni. Un file costruito manualmente
non deve essere dettagliato come quello del backup
"da lasciare com'è". Per esempio scrivo che il campo
updated_at, anche se lo metti, viene ignorato.
Che il campo deleted_at serve metterlo solo per
indicare che un record cancellato va ripristinato
e non scrivendo 'null' ma la parola 'restore',
che il parser yaml passa avanti.
Il job di importazione dovrà per forza essere
diverso da quello "semplificato" della lettura file di backup.
Di fatto dovrà agire come sostituto dell'input
a video delle blade *modify* per i modelli
UserContact, UserWork, UserWorkMore.

Problema risolto: mettere i file da scaricare nella cartella delle
immagini NON consente lo scarico, viene sempre presa dentro lo
script di LaRecipe, quindi la soluzione più semplice
è stata spostare i file in una cartella diversa, fuori
da `/storage/app/public/docs/`.
