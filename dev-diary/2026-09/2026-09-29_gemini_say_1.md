## Domanda 1

*Allegati i model User, UserContact, UserRole, e altri user* *

Ci sono user partecipanti a concorsi e altri che sono tramite UserRole con role 'juror' associato a un contest_id valorizzato. Devo quindi selezionare i giurati ordinandoli per Country_id, per last_name, first_name, created_At ma che abbiano anche un ruolo di giurati in qualche concorso. Tenendo conto degli eager loader, come devo impostare la query?

## Risposta 1

Per selezionare gli utenti che svolgono il ruolo di giurati (`role = 'juror'`) in almeno un concorso (`contest_id` non nullo e attivo) e ordinarli per Paese, Cognome, Nome e Data di Creazione dell'utente, la query Eloquent va impostata facendo un **`join` con `user_contacts**` (dove risiedono `country_id`, `last_name` e `first_name`) e un filtro **`whereHas` sulla relazione `userRoles**` (o `activeUserRoles`).

Ecco la struttura consigliata della query, inclusa l'impostazione degli eager loader per evitare il problema N+1:

```php
use App\Models\User;
use App\Models\UserRole;

$jurors = User::query()
    // 1. Join necessario per ordinare sui campi del profilo/contatto
    ->join('user_contacts', 'users.id', '=', 'user_contacts.id')
    
    // 2. Filtro per verificare l'esistenza del ruolo di giurato in un concorso
    ->whereHas('userRoles', function (\(query) {\)query->where('role', UserRole::JUROR)
              ->whereNotNull('contest_id')
              // Se la validità temporale del ruolo è richiesta:
              ->where('role_opening', '<=', now())
              ->where('role_closing', '>=', now());
    })
    
    // 3. Eager Loading delle relazioni utili
    ->with([
        'userContact.country', // Carica il contatto e il relativo paese
        'userRoles' => function (\(query) { // Carica solo i ruoli da giurato associati ai concorsi\)query->where('role', UserRole::JUROR)
                  ->whereNotNull('contest_id');
        }
    ])
    
    // 4. Ordinamento richiesto
    ->orderBy('user_contacts.country_id', 'asc')
    ->orderBy('user_contacts.last_name', 'asc')
    ->orderBy('user_contacts.first_name', 'asc')
    ->orderBy('users.created_at', 'asc')
    
    // 5. Seleziona le colonne di `users` per evitare sovrascritture di ID a causa del join
    ->select('users.*')
    ->get();

```

---

### Dettagli e Accorgimenti Chiave

1. **`select('users.*')`**: Poiché `users.id` e `user_contacts.id` coincidono (relazione 1:1), fare un `join` senza esplicitare le colonne selezionate potrebbe sovrascrivere o sporcare gli attributi dell'istanza del modello `User`.

2. **Ordinamento su relazioni**: Eloquent non permette di fare `orderBy` diretto su relazioni `HasOne` o `HasMany` senza un `join` esplicito a livello di Query Builder database. Per questo motivo viene effettuato `join('user_contacts', ...)`.
3. **Eager Loading (`with`)**:

* Previene il problema N+1 quando si accede ai dettagli dell'utente e ai suoi ruoli nella vista/controller.
* La closure dentro `with(['userRoles' => ...])` restringe le relazioni caricate in memoria ai soli ruoli pertinenti al concorso/giuria, escludendo eventuali altri ruoli dell'utente (ad es. `admin` o ruoli di organizzazione).
