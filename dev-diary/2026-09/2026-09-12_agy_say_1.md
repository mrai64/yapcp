    namespace App\Jobs;
    
    use App\Models\Contest;
    use Illuminate\Contracts\Queue\ShouldQueue;
    use Illuminate\Foundation\Queue\Queueable;
    use Illuminate\Support\Facades\Log;
    use Illuminate\Support\Facades\Storage;
    
    class DumpContestModifyNameFieldsJob implements ShouldQueue
    {
        use Queueable;
    
        /**
         * Create a new job instance.
         *
         * @param Contest $contest L'istanza del concorso da esaminare
         * @param string|null $outputFile Percorso opzionale su Storage (es.
  'exports/contest_fields.txt')
         */
        public function __construct(
            public Contest $contest,
            public ?string $outputFile = null
        ) {
        }

        /**
         * Execute the job.
         */
        public function handle(): string
        {
            $fieldsDefinition = $this->getFieldsDefinition();
            $outputLines = [];
    
            foreach ($fieldsDefinition as $field) {
                $label = $field['label'];
                $wireModel = $field['wire_model'];
                $attribute = $field['attribute'];
                $rule = $field['rule'];
    
                // Recupera il valore dal model (con formattazione per tipi speciali)
                $rawValue = $this->contest->{$attribute};
                $valueFormatted = match (true) {
                    is_bool($rawValue) => $rawValue ? 'true (Sì)' : 'false (No)',
                    is_null($rawValue) => 'null',
                    default => (string) $rawValue,
                };
    
                // Riga 1: Label del campo: Contenuto
                $outputLines[] = "{$label}: {$valueFormatted}";
    
                // Riga 2: Commento con nome campo (wire:model e colonna DB) e regola di
  validazione
                $outputLines[] = "// {$wireModel} ({$attribute}): {$rule}";
                $outputLines[] = ""; // Spaziatore
            }

            $result = implode("\n", $outputLines);
    
            // Se specificato un file, salva su disco (es. storage/app/private o public)
            if ($this->outputFile !== null) {
                Storage::disk('local')->put($this->outputFile, $result);
            }
    
            // Scrive anche nei log di sistema
            Log::info("Dump campi Contest [{$this->contest->id}]:\n" . $result);
    
            return $result;
        }

### 2. Come interpretare i Token Speciali

  Il Job complementare di importazione risolve i token nel seguente modo:

  1. Contest ID:
      • new: indica che deve essere creato un nuovo concorso. Poiché Contest.php utilizza il
      trait HasUuids, Laravel genererà automaticamente un nuovo UUID v4.
      • <uuid>: cerca il concorso tramite Contest::findOrFail($uuid) per aggiornarlo.
      • find:<nome_o_slug>: cerca il concorso per name_en (es. find:10th Grand Photo Cup 2026).
  2. Organization:
      • <uuid>: cerca per ID primario Organization::findOrFail($uuid).
      • find:<nome>: cerca per nome Organization::where('name', $nome)->firstOrFail().
      • first: seleziona la prima organizzazione a cui appartiene l'utente corrente.
  3. User Contact / Creator:
      • find:<email>: cerca l'utente tramite email User::where('email', $email)->first()->contact.
      • Se omesso o current, usa Auth::user()->contact.

### 3. Implementazione del Job Complementare: ImportContestModifyNameFieldsJob

  Ecco come appare il Job che legge l'output testuale, lo valida ed esegue l'inserimento o
  l'aggiornamento:

    <?php
    
    namespace App\Jobs;
    
    use App\Models\Contest;
    use App\Models\Organization;
    use App\Models\User;
    use App\Models\UserContact;
    use Carbon\CarbonImmutable;
    use Illuminate\Contracts\Queue\ShouldQueue;
    use Illuminate\Foundation\Queue\Queueable;
    use Illuminate\Support\Facades\DB;
    use Illuminate\Support\Facades\Validator;
    use Illuminate\Validation\ValidationException;
    
    class ImportContestModifyNameFieldsJob implements ShouldQueue
    {
        use Queueable;
    
        public function __construct(
            public string $textContent
        ) {
        }
    
        public function handle(): Contest
        {
            return DB::transaction(function (): Contest {
                $parsed = $this->parseContent($this->textContent);
    
                // 1. Risoluzione Organizzazione
                $organization = $this->resolveOrganization($parsed['metadata']['organization_id']
  ?? null);

                // 2. Risoluzione Contatto / Utente
                $creator = $this->resolveCreator($parsed['metadata']['contact_id'] ?? null);
    
                // 3. Validazione dinamica dei campi sfruttando le regole estratte dai commenti
                $validator = Validator::make($parsed['attributes'], $parsed['rules']);
                if ($validator->fails()) {
                    throw new ValidationException($validator);
                }
    
                $validatedData = $validator->validated();
    
                // 4. Risoluzione o Creazione del Contest
                $contestIdentifier = $parsed['metadata']['contest_id'] ?? 'new';
                $contest = $this->resolveOrCreateContest($contestIdentifier, $organization,
  $creator);

                // 5. Assegnazione attributi e salvataggio
                $contest->fill($validatedData);
                $contest->save();
    
                return $contest;
            });
        }
    
        /**
         * Esegue il parsing riga per riga di Label: Valore e del commento // wireModel (attr):
  rules
         */
        protected function parseContent(string $text): array
        {
            $lines = preg_split('/\r\n|\r|\n/', $text);
            $attributes = [];
            $rules = [];
            $metadata = [];

            $currentLabel = null;
            $currentValue = null;
    
            foreach ($lines as $line) {
                $line = trim($line);
                if ($line === '' || str_starts_with($line, '#')) {
                    continue;
                }
    
                // Riga di commento: // wireModel (attribute_name): rule1|rule2
                if (str_starts_with($line, '//')) {
                    if (preg_match('#//\s*(\w+)\s*\((\w+)\):\s*(.+)#', $line, $matches)) {
                        $attribute = $matches[2];
                        $rule = trim($matches[3]);
    
                        // Gestione valori booleani e null
                        $castedValue = match ($currentValue) {
                            'null' => null,
                            'true', 'true (Sì)', 'true (Si)' => true,
                            'false', 'false (No)' => false,
                            default => $currentValue,
                        };
    
                        // Se fa parte dei metadati di controllo
                        if (in_array($attribute, ['id', 'organization_id', 'contact_id'])) {
                            $metadata[$attribute === 'id' ? 'contest_id' : $attribute] =
  $castedValue;
                        } else {
                            $attributes[$attribute] = $castedValue;
                            $rules[$attribute] = $rule;
                        }
                    }
                    $currentLabel = null;
                    $currentValue = null;
                    continue;
                }

                // Riga di dato: "Label: Valore"
                if (str_contains($line, ':')) {
                    [$label, $val] = explode(':', $line, 2);
                    $currentLabel = trim($label);
                    $currentValue = trim($val);
                }
            }
    
            return [
                'metadata'   => $metadata,
                'attributes' => $attributes,
                'rules'      => $rules,
            ];
        }
    
        protected function resolveOrganization(?string $identifier): Organization
        {
            if (!$identifier) {
                throw new \InvalidArgumentException('Organization identifier mancante.');
            }
    
            if (str_starts_with($identifier, 'find:')) {
                $name = trim(substr($identifier, 5));
                return Organization::where('name', $name)->firstOrFail();
            }
    
            return Organization::findOrFail($identifier);
        }
    
        protected function resolveCreator(?string $identifier): ?UserContact
        {
            if (!$identifier) {
                return null;
            }
    
            if (str_starts_with($identifier, 'find:')) {
                $email = trim(substr($identifier, 5));
                $user = User::where('email', $email)->first();
                return $user?->contact;
            }
    
            return UserContact::find($identifier);
        }
    
        protected function resolveOrCreateContest(string $identifier, Organization $organization,
  ?UserContact $creator): Contest
        {
            if ($identifier === 'new') {
                // Inizializza come in make.blade.php con valori di default e calendario a +1
  anno
                $contest = new Contest();
                $contest->organization_id = $organization->id;
                $contest->country_id = $organization->country_id;
                $contest->timezone_id = $creator?->timezone_id ?? 'Europe/Rome';
                $contest->day_1_opening = CarbonImmutable::now()->addYear()->startOfDay();
                $contest->day_2_closing = CarbonImmutable::now()->addYear()->addMonths(3)-
  >endOfDay();
                $contest->day_3_jury_opening = CarbonImmutable::now()->addYear()->addMonths(3)-
  >addDays(15)->startOfDay();
                $contest->day_4_jury_closing = CarbonImmutable::now()->addYear()->addMonths(4)-
  >endOfDay();
                $contest->day_5_revelations = CarbonImmutable::now()->addYear()->addMonths(4)-
  >addWeek()->endOfDay();
                $contest->day_6_awards = CarbonImmutable::now()->addYear()->addMonths(4)-
  >addWeeks(3)->endOfDay();
                $contest->day_7_catalogues = CarbonImmutable::now()->addYear()->addMonths(5)-
  >endOfDay();
                $contest->day_8_closing = CarbonImmutable::now()->addYear()->addMonths(6)-
  >endOfDay();
                return $contest;
            }

            if (str_starts_with($identifier, 'find:')) {
                $name = trim(substr($identifier, 5));
                return Contest::where('name_en', $name)->firstOrFail();
            }
    
            return Contest::findOrFail($identifier);
        }
    }

▸ Thought for 2s
  Evaluating Asynchronous vs Orchestrated Jobs
  La risposta sintetica è: ti conviene assolutamente spezzettare la logica (Single
  Responsibility), ma NON ti conviene eseguirli in asincrono parallelo.
  La soluzione architetturale ideale in Laravel è avere un Job "cappello" asincrono
  (l'Orchestratore) che esegue le varie parti in sequenza e dentro un'unica transazione di
  database atomica.

  Ecco un'analisi tecnica dettagliata dei motivi, dei rischi dell'asincronia pura e del pattern
  raccomandato per il tuo caso.
  ──────

### 1. I 3 rischi dell'Asincronia Pura per entità relazionali

  Se lanciassi contemporaneamente in coda job asincroni separati (ProcessPatronageJob,
  ProcessSectionJob, ProcessJuryJob):

  1. Race Condition sulle Foreign Key (Vincoli di integrità):
      • ContestJury richiede obbligatoriamente contest_id e section_id (contest_sections.id).
      • Se ProcessJuryJob parte prima o contemporaneamente a ProcessSectionJob, fallirà
      immediatamente con un errore di chiave esterna (Integrity constraint violation) perché la
      sezione non esiste ancora a database.
  2. Perdita dell'Atomicità (Niente Rollback transazionale):
      • Una transazione database (DB::transaction()) vive all'interno di un singolo processo PHP.
      • Se spezzetti in job asincroni distinti, ognuno avrà la propria transazione. Se la
      creazione delle sezioni va a buon fine, ma il job della giuria o dei premi fallisce per un
      errore di validazione, ti ritroverai nel database con un concorso incompleto, orfano o
      incoerente, senza possibilità di fare rollback automatico.
  3. Overhead inutile:
      • La configurazione di un concorso ha volumi contenuti (1 concorso, 2–6 sezioni, 3–10
      giurati, qualche patrocinio e premio).
      • Inserire in coda 6 job separati, fare 6 volte il bootstrap del framework e della
      connessione worker genera molto più overhead di quanto ne richieda salvare tutti i record
      in un'unica esecuzione (che richiede pochi millisecondi).

                }

  entità.");

                return $contest;

### 4. Vantaggi di questo approccio

  1. Massima Pulizia del Codice (SRP): Ogni classe Action (SyncContestPatronagesAction,
  SyncContestSectionsAction, ecc.) si occupa di validare e persistere un solo modello e le sue
  regole.
  2. Sicurezza ACID al 100%: Se un codice federazione in ContestPatronage è errato, o un giurato
  non esiste, scatta una ValidationException e il rollback annulla tutto, evitando che rimanga un
  concorso "monco" a metà.
  3. Mappatura Naturale degli UUID: Non hai bisogno di indovinare gli UUID generati per le
  sezioni: la funzione delle sezioni ti restituisce la mappa (es. ['COL' => 'uuid-sezione-
  colore']), e l'azione successiva della giuria assegna direttamente l'UUID corretto al campo
  section_id.
  4. Eseguibile sia da Web che da CLI/Queue: Puoi chiamare
  SyncContestAggregateJob::dispatch($testo) da un form web o via API in asincrono, oppure
  chiamare direttamente $job->handle() da un comando Artisan / test Pest in modo immediato.
